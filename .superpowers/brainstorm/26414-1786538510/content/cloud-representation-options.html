A · 水平/垂直解耦（推荐）

冻结 Sₕ=120 的 weather/shape 大尺度，只测试 V=8/16/24 的层厚；密度按 1/V，步长由层厚和最低采样数推导。继续使用原生 Clouds → temporal → AerialPerspective。

优点

  • 最接近现有实现
  • 直接修复贴地和平板感
  • 仍可接 V3

代价

  • 放弃“单一 S 相似缩放”
  • 属于 orbital art contract

B · 缩小整个行星体系

把 Earth、相机、云层和大气一起缩小，让 Takram 官方公里尺度在投影里变大，获得真正的几何相似性。

优点

  • 数学合同最干净
  • 官方参数最少改动

代价

  • 重开 scene depth/ECEF/大气单位
  • 影响 LuBirth 现有地球与相机

C · 专用轨道云壳

opening 使用专门的 2.5D/低步数云壳，Takram 仅保留近景或后续镜头；优先保证远景轮廓和性能。

优点

  • 最快获得可读远景
  • 成本最容易压到 3 ms

代价

  • 不是 Takram 单一路径
  • 近景切换需额外设计

我的建议：选 A。先用最小候选矩阵证明“可见高度 + 体积层次 + BSM”，再接 V3 和 GPU 门槛；不要继续调 mip，也不要先做 temporal/adaptive 重构。
